# 闯关记录同步提示回归

运行 `python3 Tools/validation/RecordSync/run.py`。脚本使用独立 Unity 项目和随机本地 HTTP 端口，执行真实 `Match3DGameRecords` 组件；账号、游戏场景及红包组件使用桩。不会连接生产服务、读取手机数据或操作主项目编辑器。

覆盖旧格式缓存迁移、重启去重、当前账号隔离、请求途中切换账号、HTTP 400/409 原因保存、同账号本次启动提示去重、503 补传、401 登录恢复、非 JSON 错误响应及缓存上限保护。请求计数另行检查永久拒绝不重传、临时错误和登录过期会重传。测试等待时间包含真实指数退避。

结果位于 `work/record-sync/runtime/result.txt`，请求计数位于同目录的 `requests.json`，编译和运行日志位于 `unity.log`。

2026-11-11 验证：17 项记录运行断言与请求计数检查通过；现有 TestPlayerRewards 的 13 项断言与请求协议检查通过。完整运行脚本的编辑器及 WebGL 条件分支编译通过，仅有既有警告。首次测试的 15 秒等待不足以覆盖连续失败后的指数退避，改为 45 秒后全量通过；生产退避逻辑未修改。

## 修复边界

- 旧 `rejected` 记录原始内容保留，迁移为已提示；新失败保存 HTTP 状态、服务端错误摘要（最多 512 字符）、失败时间、已提示状态。
- 提示按记录所属账号处理。同账号单次启动最多提示一次，已处理提示持久化，不在下次启动重复。
- 网络/服务暂时故障继续补传，401 继续恢复登录；400/409 仍保留待诊断，不能盲目改写原始成绩或重复提交无效记录。
- 这解决重复弹窗与诊断信息缺失，不代表已定位或补回手机历史记录最初的校验失败。
- 手机端需要新小游戏包；独立运行测试和条件分支编译不等同于完整 WebGL 构建或微信真机验证。
