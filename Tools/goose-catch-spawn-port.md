# goose-catch 开场生成移植

来源：https://github.com/Yuming0929/goose-catch
固定版本：028e75a21e25e8199385934633b8ff1759f24d59。

这是作者自己的 React + Rapier 实现，不能据此认定是商业《抓大鹅》的原始算法。

## 源码行为

- `src/components/Items.tsx`：按序号计算坐标，横向每排 10 个、每排高度递增，深度每 50 个递增；出现时间为 `index / 90` 秒。
- `src/components/Item.tsx`：定时后才创建可见模型及刚体，没有额外的缩放生长动画；初始旋转未随机化。
- `src/Experience.tsx`：普通重力为零，中心 Attractor 的 strength 为 0.1、range 为 20。
- `@react-three/rapier-addons@5.0.0`：默认 static 模式，每个物理步向中心施加恒定冲量，不是距离平方反比引力。
- 源项目固定 105 件、7 种、6 个槽位，没有我们现有的每日分层难度和 PVP 服务。

## Unity 接入

`GooseSpawnMotion.cs` 移植坐标、逐个出现时间和中心吸引运动。容器坐标统一缩放为 0.6 并平移至现有锅中心；冲量和作用范围相应缩放。保留现有原版模型的质量、碰撞体与阻尼，因此 PhysX 与 Rapier 的碰撞结果不会逐帧相同。

`ReplicaFlow.cs` 按实际出现序列创建模型，使用绝对截止时间保证低帧率时同一帧可补齐多个物品。取消原先全量生成、随机旋转和普通重力下落。全部生成后留 1.5 秒落入容器，再开始计时或向 PVP 服务报告 loaded。回首页、重开和离开对战会取消未完成的生成协程。

保留教程 12 件、难关 144 件、PVP 96 件及七槽规则，物品种类仍由原有种子和分层配额决定。旧层配置的 height 不再参与出生位置，位置改由上述开源算法统一计算。中心吸引力在游戏中持续生效，支持拿走物品后自动向中心补位。

## 验证结果

Unity 编辑器单机验证全部通过，包括渐进生成、开场不扣时间、关闭普通重力、12/144 件数量、物品不穿底、三消通关、撤回、七格失败、收藏和返回首页取消生成。首次测试在编辑器切换播放模式期间过早检查首页而失败，编辑器完成编译后重新运行全部通过。

公网 PVP 使用独立 Node 客户端与 Unity 原生 WebSocket 联调：96 件加载完成后开局、服务端确认拾取、对手认输结算全部通过。此次没有修改或重新部署后端。
