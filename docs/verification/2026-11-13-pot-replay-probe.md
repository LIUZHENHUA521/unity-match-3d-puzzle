# 每日第二关道具与探物回放

## 实现

- 协议 pot-replay-v2 / pot-replay-resources-2；兼容读取旧 v1 录像。新高手查询显式传资源版本，旧客户端不会收到 v2 高手录像。
- 每帧保存四列探物实际目标 ID、连消/星数、生成飞星、提示状态、圆环动画名/进度/透明度、定位预览、并发激活与音效进度、吸附高亮、道具粒子种子/时间/变换、暂存背景。
- 探物生成、使用、定位和道具使用产生独立事件，并在该渲染帧触发采样。事件随本地帧日志保存，中断恢复保留已经落盘的事件；结束事件先于最终帧落盘。
- 回放恢复实际状态，不调用取物、随机奖励或库存扣减。暂停冻结画面与音频；拖动静默恢复，继续时从相应音频进度播放。退出恢复本人探物教学状态。
- 控制条移至顶部，保留锅内、探物区与槽位。沿用缩放锅的倍率按钮。
- 保留同期已提交的第二关云存储直传与64MiB展开上限（bd0d117e / b834b8b / c80c7c5），没有覆盖上传修复。

## 已执行验证

- Unity 实际场景：实际生成两个被遮挡目标、定位预览、两个探物并发使用、移出/洗牌/加时、连续两次吸附；真实录制后序列化并用播放器加载。
- 顺序跳转：末尾→生成→预览→双激活→暂存→生成→双激活→末尾。核对每列的实际目标 ID、连消/星数、激活数量、预览和暂存背景；探物按钮保持不可交互。
- 暂停冻结激活时间与声音，2倍播放推进表现时钟；终帧仍有音效时保持暂停；断连圆环恢复正确动画；退出不污染教学状态。
- 同一实录经过 Node 正式协议校验，验证跨语言字段和白名单没有丢失探物表现。
- 服务端118项测试通过，包含v1兼容、v2完整状态、无效目标/重复绑定/越界/未知动画拒绝，以及旧客户端资源过滤。
- 后台云函数3项、iframe来源及微信文件桥2项测试通过；管理前端构建通过。

## 限制
