# 回放可靠性修复与验证 — 2026-11-16

## 实现

- 每账号、每局保存 recording/queued/uploading/synced/failed 状态、对局日期与档位、失败原因和重试时间。首页云端可播放录像优先；没有完整文件的胜局显示“本局回放未保存”，上传中显示“回放同步中”。通关结算不依赖录像成功。
- 保留 10 Hz 采样与全部操作事件；位置/缩放写 3 位小数，四元数写 4 位小数；四元数归一化后比较；与最后实际写出的状态比较，避免缓慢移动累积丢失；冻结不可见物体的运动，完整快照间隔 30 秒。
- 通关录像优先，同优先级按等待顺序处理。网络、认证、服务暂不可用与临时压缩 I/O 错误保留完整文件，5 秒到 5 分钟退避，无最大重试次数。完整旧 rejected 文件仅在本次修复版本尝试恢复一次，永久校验失败继续隔离保存。
- 初始化恢复限于当前账号，清理中断遗留的 upload 临时包；单个坏文件不阻塞其他队列项；超过 7 天的明确失败残片才可清理，完整 queued/rejected 文件不自动删除。无文件的终态诊断元数据保留 30 天。
- 新增现有 /pot-replays/ 下的 diagnostic 操作，客户端按队列持久化重试上报，服务端按登录账号与对局绑定，限长、校验参数、防旧状态覆盖新状态。诊断保存在原对局的 potReplayDiagnostic 字段，不改变游戏结果。
- 服务端允许 30 秒检查点；旧版全部不可见物体越界下落时仅修正位置为上一合法位置，继续拒绝可见越界、非有限值、非法物体及其他无效数据。

## 验证

- Unity 长局与本地队列测试：330 个物体、18,001 帧、30 分钟合成场景（12 个可见移动物体、静态随机旋转与抖动、消失转换、完整快照）。JSON 42,194,777 字节，gzip 1,776,523 字节。验证随机时间定位、缓慢移动、状态持久化、退避上限、账号隔离、胜局优先、重启恢复、旧拒收文件仅重试一次、完整隔离文件保留、失败残片清理、旧 pending 元数据导入；另验证 1,000 个不同旋转的静态四元数不会被误报为移动。
- Unity 首页真实 HTTP fixture：无文件胜局、等待/上传/失败文案、服务失败保留文件并重试、服务已完成时免重传、分页查找、账号切换、下载失败与取消、完整进入播放器及退出均通过。
- 原有 Unity 流式 gzip 回归通过：30,960,037 字节原始文件，700 帧，完成时托管内存增量 114,688 字节；旧 pending 流式压缩和中断恢复通过。
- JS 原生文件桥 2 项测试通过；服务端完整测试套件 159 项通过（含诊断权限、输入限制、30 秒快照、旧隐藏越界数据归一化）。
- 这是合成场景与 Unity 编辑器/本地 HTTP 验证，不等于微信真机连续 30 分钟验收。
