# iOS 通关内存不足：回放链路修复

用户反馈 iPhone 17 Pro 通关后被微信小游戏以“运行内存不足”退出；客户端具体版本未知，尚无设备内存日志。代码确认存在高峰值路径：Recorder 累积全部帧对象，Finish 整局 JsonUtility.ToJson，队列再 ReadAllText，UTF-8 整包复制，内存压缩/加密，UnityWebRequest 再复制上传。这是明确风险，不能仅凭截图断言为唯一退出原因。

## 修改

- 录制仅保留初盘、最新物体状态与有上限的事件列表；历史帧持续写 JSONL，约32K字符即落盘。
- 通关只写小型 `.ready` 清单，保留 `.recording` 文件，不组装整局字符串、不压缩。
- 空闲时逐帧/32KiB读取，gzip/AES直接写磁盘；微信上传仅在原生JS侧读取压缩文件，不把整包原文或上传字节数组复制进WASM。
- 旧 `.pending` 队列按32KiB流式处理；未完成记录逐帧恢复，最后完整检查点写入清单，截断尾帧不进入上传。
- Unity低内存事件和微信内存告警停止录制、取消上传并暂停60秒；已经落盘的数据保留，正常结算路径不变。
- 云端协议和接口不变，无需部署服务端或后台。

## 已验证

- Unity隔离编译与30,960,003字节、700帧回放测试通过；完成清单保存步骤的托管内存增量114,688字节，压缩加密文件807,312字节。这不是iOS整进程峰值测量。
- 同一大录像输出经Node解密解压，通过正式服务端协议校验（700帧、完整结束事件）。
- Unity实际第二关录制测试：历史帧列表始终为空，清单/文件生成正常；回放暂停、向后跳转、只读退出验证通过；实际v2输出通过服务端校验。
- 旧17MiB队列兼容压缩、截断尾帧恢复测试通过。
- 微信文件桥测试3项通过：跨UTF-8边界二进制分块、最大32KiB读取、原生上传只读取压缩文件、成功与取消后的任务释放、超大压缩文件拒绝。

## 待验证

微信端构建及iPhone 17 Pro真机长局通关/断网重试。没有将本地托管内存测试结果当作真机修复验收。
