# Match3D 命名迁移

本次将复刻阶段的工程命名整理为业务命名，不改变实现的来源，也不声明这些实现为原创。

## 范围

- `Assets/GooseReplica` → `Assets/Match3D`，场景改为 `Assets/Scenes/Match3D.unity`。
- Resources 命名空间 `Replica/` → `Match3D/`，同步编辑器、构建脚本、微信桥接测试和场景构建配置。
- 堆叠、物理、对象池、关卡配置分别命名为 `LayeredItemPile`、`ItemPhysicsController`、`BoardItemPool`、`LevelLayoutConfig`；其余通用游戏组件使用 `Match3D` 前缀。
- `RecordSourceTouchHeight` → `RecordSelectionHeight`。完整映射见 [命名表](2026-11-04-naming-map.json)。
- 部分入口注释改为解释实际行为，原文与新文逐项保存在 [注释来源记录](2026-11-04-comment-provenance.json)。

## 行为与兼容性

算法、常量、随机调用顺序、动画时序不变。保留资产 `.meta` GUID，脚本与同名 `.meta` 一起迁移。没有更改序列化字段、JSON 字段、存档键 `goose.*`、微信桥接的外部函数名或模型标识，以保持现有配置、进度和接口兼容。因此工程中仍有 `Source`、`GooseArt` 等数据和兼容性名称。

未改动历史证据、备份和既往验证报告。历史证据中的旧路径按本次命名表对应到新路径；`Tools/LayeredPile/Evidence` 中的历史导出脚本仍保留当时的路径，不能直接当作当前构建入口。当前构建入口为 `Tools/wechat/build.py`。

## 实现与数据来源

命名迁移不抹去以下既有来源信息，也不改变任何第三方许可和署名要求：

- 商业《抓大鹅》的已检查包、元数据、资源及行为，是部分数据与行为重建的依据。WX 2.1.12 的 MainLevel/第二关配置行（1、4、5）对应关卡配置；`j1345` 对应共享随机数入口；`LevelObjectPool.Get/Recycle` 对应对象复用行为；`GetUnit`、`SetMinTouchHeight`、`BeClick`、`CheckRigid` 对应拾取高度和刚体阈值行为。
- 固定相机参考 `CameraControl.Start`、`ScreenMa.GetScreenOffset(1,0)` 及 `LevelManager` 的 flatTopView 模式。详细证据保留在 [相机对齐记录](../../Tools/LayeredPile/camera-shadow-alignment.md)。
- 第三方 React/Rapier 仿作与商业原版的区别，以及曾移植的生成方案，保留在 [生成移植记录](../../Tools/goose-catch-spawn-port.md) 和 [物理参考记录](../../Tools/goose-physics-reference.md)。历史物理记录不是当前参数清单。
- 收纳槽参考与素材来源保留在 [收纳槽记录](../../Tools/tray-reference.md)。其他素材、音频及第三方组件的既有许可文件不变。

## 验证

- Unity 2022.3.62f3c1 批处理编译通过。
- 静态检查确认 1838 个迁移 `.meta` GUID 保持不变；171 个 C# 文件的可执行内容仅按命名表替换。入口注释的后续调整另行核对。
- PlayMode 验证：全部 Match3D 预制体和主场景无丢失脚本；主页资源加载、随机序列与生成回放、道具选择/打乱规则、对象池复用通过。
- 第一关为 12 个普通物体加 3 个目标物体，第二关为 300 个物体；拾取入槽、撤回恢复、三消清除和返回主页清场通过。临时验证最初误用了旧测试中的第一关 12 个总物体断言，按当前生成代码校正为 15；未因此改动游戏逻辑。
- 详细结果见 [运行时检查](2026-11-04-runtime-validation.txt) 与 [静态检查](2026-11-04-static-checks.json)。
- 微信传输、资料、邀请、客服、复活广告、游戏圈和字体桥接共 19 项测试通过，见 [桥接测试](2026-11-04-bridge-tests.txt)。修改后的 6 个 Python 工具脚本通过语法解析；最终 Unity 编译再次通过。
