# 道具库存与分享／广告（2026-11-12）

四个单人道具（移出、吸附、洗牌、加时）共用一个获取序列，清槽与超时复活共用另一个独立序列。两个入口均采用前置「分享一次、广告一次」，后续循环「分享一次、广告一次」。计数按账号和入口保存在本机，跨关卡与重启保留；库存使用不推进序列。

点击先检查玩法条件（例如空槽不能移出/吸附、洗牌进行中），不满足时仅提示。有免费额度时先显示免费使用弹窗，否则库存已连接且有数量时通过原 consume/refund 流程扣减并执行，最后进入分享／广告弹窗。库存请求进行中或存在未完成扣减时提示稍后重试。

道具说明复用 ReviveClear 布局，按实际分支显示“免费使用”“分享并使用”“看广告并使用”。复活也显示对应文案。弹窗期间暂停计时，关闭恢复。成功获取只授权本次执行，不增加永久库存；仅效果实际生效后推进次数。回调绑定账号、关卡及弹窗版本，重复或失效回调不发放。

`RewardAcquisitionConfig.json` 配置前置/循环、两个入口各自每关免费额度、广告/分享开关及分享返回间隔。默认免费额度 0；每次开始/重试关卡重置免费额度，免费不推进交替序列。关闭广告时转分享，关闭分享时转广告，全部关闭且无免费资格则不能领取；已有库存仍可正常消费。此为客户端配置，尚未接运营后台远程下发。

分享桥接使用隐藏后至少 3 秒再返回的本地判定，不证明好友收到分享。快速返回、调用失败、等待超时不发放；停留够时长后的取消无法可靠识别。真机需验证微信版本下的前后台事件。广告只接受 `isEnded === true`；失败允许原步骤重试。

`RewardedVideoConfig` 的三个广告位保持现状。使用统计中 free 为真实免费次数，rewarded 包含分享和广告；二者不会误算为永久库存消费。

验证入口：`RewardAcquisitionValidation.Run` 为 Unity 实际场景联调，`node Tools/wechat/test-reward-share.cjs` 与 `node Tools/wechat/test-revive-ads.cjs` 为桥接验证。原广告专用验证显式关闭分享；库存部分仍使用本地模拟服务。微信 SDK 实际分享与播放需要真机验收。
