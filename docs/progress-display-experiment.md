# 进度展示实验

实验 key：`goose_progress_display_ab`，只作用于一锅消不完（`wx74f2d8722c02a6f4`）。共用后台的 AB 实验管理中维护，无独立后台页面。

| 组 | 深层隐藏物品权重 |
|---|---|
| A | 1，真实消除比例 |
| B | 0.5 |
| C | 0.7 |
| D | 0.3 |

100% 的符合条件用户参与，沿用服务端确定性分组，四组长期约各 25%，不是每批人数严格均分。注册时间下限以线上配置为准，默认新用户。手工体验账号固定 B，`manualOverride: true`，正式分析排除。

## 计算及生命周期

`已消除 / (已消除 + 未隐藏剩余 + 权重 × 深层隐藏剩余)`。

隐藏状态取 `LayeredItemPile.HiddenCount`，对应现有深层渲染隐藏规则，不做屏幕几何遮挡检测。槽位及暂存物品仍在 `objectsOnScene`，且已经从 pile detach，因此按未隐藏剩余计数；仅真正消除的物品贡献分子。

开挑战时读取 `Match3DABExperiments.GetABGroup` 并锁定。第二关和重试继承同组，但每关/次重试归零；复活延续进度。每 0.2 秒及弹窗显示时采样，按单局最高值展示，未通关上限 99%，真正胜利 100%。复活和结算调用同一个方法。A 沿用真实最佳成绩 key；B/C/D 用独立的 `.progress_v1_<group>` 后缀。

实验不改变真实关卡记录、奖励判定、剩余数量标签及 PVP。缺失/未知/过期分组回退 A；启动等待 AB 最多 3 秒，不无限阻塞登录。回收数据时应按首次命中时间和挑战开始时间筛选有效曝光，关注网络超时导致的回退。

## 旧版兼容

新版 `/invites/ab` 请求携带 `X-Goose-Progress-Display: 1`。服务端把能力 `progress_display_v1` 放入经过登录验证的短期 proof。`hitABTest` 按实验 `requiredCapability` 筛选，旧客户端不会创建这个实验的命中记录。客户端请求体无法伪造身份、指定测试或指定分组。并发不同能力请求串行处理，避免互相覆盖 proof。
