# 保留斜俯视，修复第二关物品堆偏上

两关继续共用第一关约 82° 的镜头和完整锅 Transform。第二关使用竖直的短段圆滑
容器，整体世界原点从 (0,0,0) 平移到 (0,0,-3)，局部轮廓、物品尺寸、世界 Y 高度
及重力不变。坐标转换同时覆盖生成、碰撞检查、撤回、洗牌和摇动的中心。

上一轮 (0,0,-2.5) 的画面对照测得，开局可见模型包围范围的中心仍比锅口中心高
约 4.66% 屏幕高度，因此又增加了 0.5 单位的水平平移。它通过斜俯视投影让物品
在画面上向下移动；没有在切关或消除过程中移动镜头、锅或持续追踪物品堆。
物品减少后包围范围会随高度和物品分布自然变化，并非每一帧都强制居中。

## 验证方式

使用独立 Unity 2022.3.62f3c1 快照，保留用户正在编辑的原项目。
`ContainerFramingValidation.Run` 在 720×1560 竖屏渲染完整游戏 UI 和实际物品，
对比同一盘物品取消水平平移的诊断图，并在剩余 300、150、30、3 个时记录画面。
通过真实入槽与三消流程减少物品；为便于覆盖尾局，测试直接选择匹配组，允许取到
隐藏物品，不代表真人的完整解题路线。暂停自动物理，在每次消除后按固定步数模拟。

另以 `SoftContainerValidation.Run` 检查三套模型、不同尺寸和高度下的完整碰撞边界，
以及第一关原样保留、切关、撤回、洗牌、摇动和重开。

这是编辑器验证，不是微信真机验证。本次没有修改横向尺寸；原始测量同时记录
模型包围范围的横向越界，不把上下取景修正宣称为完整的横向适配。

## 最终画面验证结果

最终原点 (0,0,-3)，`ContainerFramingValidation.Run` 退出码 0：

- 99 次真实三消，从 300 个减少到 3 个；各记录点镜头和锅 Transform 保持一致。
- 开局可见模型包围范围中心比锅口中心高约 **1.56%** 屏幕高度；上一版为 4.66%。
  这是一盘固定种子的测量值，物品种类与朝向会影响实际轮廓，不保证每盘完全相同。
- 取景检查覆盖剩余 300、150、30、3 个物品；未进入顶部 HUD 或下方槽位区域。
  低堆自然靠近锅的下半部，末尾 3 个仍位于锅内，并通过容器包含检查。
- 通过实际相机射线在可见物品区域取得 418 个有效点击命中。
