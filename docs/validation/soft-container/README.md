## 与旧版的差别

`baseline.json` / `candidate.json` 使用相同的 3 个种子、默认 300 物品主题、尺寸 1，
每次手动模拟 500 步（每步 0.02 秒）。创建期间暂停自动物理，因此这是受控对照，
不等于玩家实时生成过程或手机帧率测试。

| 指标 | 旧容器 | 短段圆滑 |
| --- | --- | --- |
| 三组露出物品数 | 122 / 120 / 121 | 117 / 112 / 117 |
| 平均露出物品数 | 121 | 115.3 |
| 500 步模拟耗时均值 | 108.9 ms | 120.0 ms |

这次样本的露出量约减少 4.7%；单次编辑器计时约增加 10%，样本不足以判断性能回归。
拾取、三消动画、物品尺寸配置和刚体参数没有为容器改形另行调整。
目前可确认功能验证通过，不能据此承诺手感完全一致。需要在微信真机试玩确认
顶部密度、中段滑落和颠锅后的堆叠是否符合预期，再决定是否微调出生密度。

本次只替换容器及必要的放置逻辑，不代表整个项目已完成独立重写或法律风险审查。

## 复现

在独立 Unity 项目快照中执行：

```sh
/Applications/Unity/Unity.app/Contents/MacOS/Unity -batchmode -nographics \
  -projectPath <snapshot> -executeMethod SoftContainerValidation.Run \
  -logFile <validation-log>
```

测试会进入 Play 模式并在完成后退出编辑器；报告写到快照上级 `results/validation.json`。
不要直接对正在编辑的项目运行该批处理入口。
