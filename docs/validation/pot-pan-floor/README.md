# 披萨藏在锅下修复（2026-11-14）

用户提供玩家 ID 和“锅已空、槽内还剩两个披萨”的截图，并反馈此前也有相同物品的问题。

## 证据与边界

- 已按 `goose_game_records.userId` 找到玩家记录。当前 `pot_replays` 没有该玩家的录像，因此不能声称已确认截图那一局的末局坐标或具体穿入时刻。
- 玩家最近使用 `tasty-kitchen`，披萨模型是 `Kitchen_pizza`。当前每日开局中的 12 个披萨均在锅面上方；所检查的 306 个位于锅面投影内的物品没有完整藏在锅下。原始开局数据仅保存在本地临时文件，未修改云端关卡或记录。
- 明确复现同类缺陷：禁用本次锅面 fitting，使用旧容器的 Y=0 底板规则放置小号 Kitchen_pizza，模拟 12 秒后可见网格最高点仍为 Y=0.04905747，低于锅面 Y=0.4846579。物体仍存在，但被锅遮住。
- 旧 `SoftTransitionContainer.FittedPosition` 只保证实体在旧底板之上；已有 MeshCollider 和连续碰撞不会自动救出已位于锅面下的物体。

## 修复

- 新增 `PotPanFloor`，绑定实际锅面碰撞体并查询对应水平位置的表面高度。
- 容器 fitting 使用真实锅面作为最低放置高度，覆盖生成和洗牌收尾。
- 生产可见性刷新时，检查仍在锅内的物品；完全低于锅面的实体被抬回锅面之上，再计算可见性和刚体状态。保持物品身份、数量、三消计数及奖励逻辑。
- 跳过生成、锁定的每日开局、道具移动，以及已从棋盘取走的物品；正常支撑/部分露出的物品不会被移动。高处物品在射线和几何检查之前快速排除。
- 绑定随展示场景回收；第一关到第二关复用展示时继续生效。
