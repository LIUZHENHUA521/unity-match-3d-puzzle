# 开局穿插修复回归（2026-11-13）

## 根因与改动

随机生成及每日快照未校验实体相交；每日开局全冻结，保存的重叠不会自动消解。原物理活动带还小于可见带，首次操作后部分可见实体仍被冻结。

新增 `BoardOpeningSeparation`，在进入 PLAY 前，按实际碰撞体修复可见物品与其他物品、容器的穿插。固定顺序和局部候选序列，不使用游戏随机数；完整复查成功才一次应用。已合法开局保持原姿态，脏布局可重新平移、旋转，但不改变类型、数量、尺寸、可见集合。旧每日快照自动修正并在当前关卡对象内缓存，未回写服务器。

可见物品全部具备物理释放资格；未操作时保持修复后的冻结状态。捕获只允许发生在该状态。新生成增加最多 2 秒结算后再修复；第二关上方增加 2 单位直壁余量，原出生高度、横向宽度与镜头不变。失败有界退出回首页，不进入坏布局。

## 验证

在隔离项目 `Builds/DailyOpeningProject` 同步生产脚本和素材，运行真实 Match3D 场景。未关闭用户正在使用的 Unity 编辑器。

```sh
/Applications/Unity/Unity.app/Contents/MacOS/Unity -batchmode \
  -projectPath Builds/DailyOpeningProject \
  -executeMethod OpeningSeparationValidation.RunBatch \
  -logFile work/interpenetration-audit/final-integration.log
```

无图形环境可添加 `-nographics`，跳过图片导出。测试依赖 `Tools/validation/OpeningSeparation/legacy-opening.json`。该数据来自项目既有导出样本，复现同类问题，并非从用户截图还原的精确局面。

- 旧样本 300 件、可见 114 件；原检测有 115 对可见物品相交，修复后超过 .011 世界单位的相交对为 0。
- 同时检查可见物品与隐藏支撑、实际锅/容器墙面，凸子体中心和完整实体顶部范围。
- 原始样本重新修复、修复后重试、闲置保持姿态一致；保留 ID、类型、尺寸和可见集合。
- 第一关 15 件、两组新生成 300 件（seed 47231、42）、对象池复用、生成中返回首页。
- 首次选择释放可见物品，并检查 10 秒后最大实体/墙体接触穿透小于 .1。动态结算存在瞬时接触误差，不承诺操作后全程零穿透。
- 超大实体验证有界失败、姿态不部分应用、Unity 全局随机状态不变。

结果见 `report.txt`，图形回归导出见 `repaired-opening.png`。接触容差以世界单位计；冻结开局验收 .011，运行时结算验收 .1，两者不可混用。图像检查确认完整物品位于镜头近平面后方，未见原样本的大块互相穿插。

## 范围

验证是本机 Unity 编辑器结果，未覆盖手机真机性能或所有最多 1200 件的候选关卡。碰撞修复有固定候选预算，特别密集或异常素材可能明确失败；失败不表示数学上无解。客户端代码尚未发布线上。工作区原有移除手机摇动的修改保持原样。
