# 注册玩家手动打款与授权标题修复

用户要求在现有共享后台注册玩家页面接入打款，并修复授权弹窗标题被蓝色飘带覆盖的问题。沿用现有商户及本游戏 AppID，无需另建后台。

## 后台打款

- 玩家行新增打款入口。弹窗先查询服务端玩家身份、当前商户的有效授权，展示金额、备注、商户及最近订单；填写 0.30–200.00 元，提交前二次确认。该范围是本入口的保守产品限制，采用现有转账函数最小金额，不代表所有微信产品的限制。
- 新增独立 adminGoosePayments 云函数，验证现有管理员 token、账号状态、同时具备 /goose-users 与 /payouts 权限。所有动作均鉴权。只接收玩家 ID、整数分金额、备注、请求 ID；OpenID/AppID/商户来自服务端，不接受浏览器指定。
- 查询 merchantTransferAuth 的当前商户授权，必须身份一致、TAKING_EFFECT 才允许提交。款项通过现有 transferCash authorized 模式，固定商户、固定订单号、不回退旧模式。
- 使用 ADMINONLY 的 goose_admin_payouts 保存订单，记录收款玩家、金额、原因、操作者、商户、创建时间、状态、微信单号。事务先写订单并在玩家记录设置未决订单锁，再调用外部付款；网络错误或未知响应标为待核实，保留原订单，禁止自动重试或另开订单绕过。
- 相同 requestId 的重复提交校验上下文并只返回/查询原订单；并发提交只允许一次外部付款。订单查询从数据库取固定商户及订单号，不信任浏览器付款参数。只有明确 SUCCESS 或 FAIL/CANCELLED 才释放玩家未决锁；NOT_FOUND/网络失败保留锁供人工核实，不自动重新付款。
- 历史查询支持查看近期订单并刷新微信状态。仅服务端确认 SUCCESS 显示到账成功。页面刷新后仍可从历史找到未决订单。
- 单元测试使用模拟支付，覆盖权限、身份、金额、重复/并发、超时、固定商户及查询结果。部署前提交推送，部署云函数及后台并验证，验证不向真实玩家付款。

## Unity 标题

CommonDialog.prefab 中 Title ribbon 当前排在 Title 后，盖住文字。调整序列化兄弟顺序、修正构建脚本并在 Configure 时保证标题在飘带之上。验证保存后的结构和实际渲染；独立构建上传修复版，不混入其他人未提交的名片改动。公众平台设为体验版仍受管理员浏览器策略限制，不绕过。
