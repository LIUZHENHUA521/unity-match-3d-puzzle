# 每日挑战回放

用户已批准每日挑战范围，实现后台排查和玩家自己的/高手回放；不覆盖普通模式和 PVP。

## 数据与播放

每关录像关联现有 recordId/runId，记录固定每日配置和初始物体目录。按 10 Hz 采样发生变化的物体世界姿态、缩放、可见性、槽位序列、剩余时间和相机；每 5 秒全量检查点。操作事件补充选中、消除、道具及复活语义。时间采用本局有效时钟，暂停不推进。录像失败不能影响结算。格式 pot-replay-v1，显式携带资源和客户端版本，不支持的版本拒绝播放。

播放器在隔离的只读模式下恢复同版资源，不运行拾取、道具扣费、物理、正常结算和埋点。恢复最近检查点并顺序应用增量支持跳转，插值连续姿态，离散状态按事件时间应用。播放器提供暂停、倍速、进度、退出。后台使用独立构建的 Unity WebGL 页面，同源消息严格验证来源与会话；不向 iframe 传账号凭据。

## 持久化与访问

客户端分段本地保存并按账号重试，服务端身份来自已有 token。每段使用幂等编号，服务端验证范围、顺序、总量和引用后完成录像；详情压缩放对象存储，摘要存 pot_replays。不完整录像不进入高手列表。自己的列表按认证用户限定，高手列表按日期、难度和配置版本限定且仅展示完整胜局。后台沿用闯关记录权限。客户端录像不作为奖励或反作弊凭证。

## 交付与验证

顺序：协议和服务端验证 → Unity 录制/播放 → 玩家入口 → 后台入口和 WebGL 桥 → 构建与自动化验证 → 已授权部署后台及其必要依赖。测试鉴权、幂等、越界、跨账号访问、损坏数据、版本不兼容、跳转一致性和播放无副作用。真机帧耗和完整实际对局由可用运行环境验证并明确报告未覆盖项。部署只提交本任务文件，保留现有 AGENTS.md 用户修改。

## 审查补充

- 一关一份；初盘创建完成开始，胜负和主动退出终止，复活继续同份。后台/本人允许查看失败、退出和中断；暂停不推进录像时钟，剩余时间另存。崩溃恢复只标 incomplete，不冒充胜局。
- 分段序号从 0 开始，单段最多 128 KiB、最多 512 段，总量 16 MiB、时长 2 小时。服务端 SHA-256 验证同序号内容不可变；全部段完整、终态检查点和事件完整并匹配认证用户的每日记录后发布。
- 稳定 ID 采用 Match3DTile.id，类型由每日配置模型目录解析。资源版本 pot-replay-resources-1，后台对应独立不可变 WebGL 构建；不同版本明确拒绝，不降级套用当前模型。
- 高手列表只展示管理员显式公开的完整胜局，返回无身份信息的摘要。后台通过已认证云函数下载并校验详情，再以同源/指定 iframe/随机会话消息直接传入 Unity，不把账号 token 或永久下载地址交给 iframe。

## 实施确认

固定初盘及 legacy daily-v1 每日关卡均通过捕获实际开局支持。录像文件使用 gzip 后 AES-256-GCM 加密；密钥只在服务端私有摘要中，后台摘要与玩家响应不含解密密钥。微信本地日志使用原生 USER_DATA_PATH 文件系统，10Hz 采样在内存缓冲、5秒检查点落盘；切后台同步缓冲。资源版本变更必须更新播放器资源版本及后台固定构建路径。
