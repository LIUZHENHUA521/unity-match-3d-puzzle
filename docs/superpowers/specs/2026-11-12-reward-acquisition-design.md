# 道具与复活获取序列

按用户提供的截图采用普通关卡规则：先检查免费资格，随后按入口已完成获取次数选择前置序列，再进入循环。默认前置和循环均为「分享一次、广告一次」。移出、吸附、洗牌、加时共用 Tool 入口；清槽和加时复活共用 Revive 入口，两个入口互不影响。PVP 保留现状。

沿用现有库存消费、视频播放与复活效果，新增统一获取策略与分享桥接；不在每个道具内维护独立计数，也不按难度或随机值选择渠道。按钮显示实际渠道，复活按钮替换原本带视频图标的烘焙图片。

截图未指定的实现选择：

- 免费额度在 Tool、Revive 两个入口分别计算，各入口内共享；开始新关卡或重试同一关卡时重置，默认均为 0，不恢复历史每种道具一次免费规则。免费优先，其次服务端已有库存，最后分享/广告获取；库存成功使用不推进获取序列。
- 获取次数使用 PlayerPrefs 按账号 inviteCode 和入口持久化，跨关卡、重启保留；未登录本地试玩使用独立 local 键。该计数不属于服务器永久库存，不承诺跨设备同步。
- `RewardAcquisitionConfig.json` 配置前置/循环、免费额度、广告/分享开关和分享返回最短间隔；`Configure` 可替换进程内配置，本次没有新增运营后台或服务端远程配置接口。
- 广告关闭时广告步骤转分享，分享关闭时分享步骤转广告；都关闭时禁用获取，免费资格仍优先。广告加载失败不自动转分享，允许同一步重试。
- 分享采用调用后隐藏、至少停留 3 秒再返回的本地判定，不视为微信证实分享送达。快速返回、已知调用失败、超时不发放。无法可靠区分停留够时长后的取消与真实分享，需微信真机验收。

仅效果实际生效后推进次数。免费使用不推进分享/广告序列。每次请求捕获账号、关卡和弹窗版本，重复或旧回调不得再次发放；异常允许重试。免费使用计入 free，分享和广告均计入现有 rewarded，避免被错误计为库存；保留客户端独立 ShareUses/AdUses 方便验证。

验证：Node VM 测试微信桥接成功/失败/快速返回/无隐藏/超时/取消/重复与监听清理；Unity 实际场景测试跨道具交替、独立复活序列、免费优先、开关、暂停恢复、失败重试及跨关卡回调隔离。原广告专用验证显式关闭分享以继续覆盖视频路径。
