# iOS 第二关生成尾段性能调整

用户已确认按本轮调查的几个点修复并自行试玩。本轮保留物体数量、随机顺序、模型尺寸、增长与高度冻结规则。

1. 移除 SourceItems 中的旧 SELECTION_OUTLINE UsePass，保留 OriginalItem 的 legacy 实现；实际选中继续由 ReplicaSourceHighlight 绘制。
2. 每个池实例显式缓存 Transform、Renderer、Collider 和 Rigidbody。缓存不序列化，不依赖 inactive 下不会运行的 Awake；碰撞形状重建时失效。Get/Recycle/注册/物理参数应用复用引用。
3. 原 2.5ms 创建预算继续生效。上一帧超过约22ms时本次切片最多创建一件，避免重物理/渲染帧继续加三件或十二件；仍保证前进，不改变增长速度和物理步长。慢帧反馈不声称是整帧硬预算，无法抢占单件 Instantiate。测试重放可显式覆盖。
4. 预热实例等首关生成完成后再逐帧补充，每类至多12件，总目标至多300件；慢帧让出一次后重新检查暂停/取消。停止首关时保留已有缓存。快通关仍可能缺少缓存，不延迟用户进入第二关。增加命中/新建计数供验证。

验证：真实Unity编译；三主题创建数量/排序/显隐/增长/冻结、暂停取消重启、对象池身份/状态/缓存引用隔离、旧描边缺失与实际高亮渲染、预热边界。编辑器结果不替代iPhone性能采样。不自动上传或覆盖用户未提交改动。
