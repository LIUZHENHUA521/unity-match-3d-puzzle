# 一锅消不完广告与分享频次配置

## 已确认需求

用户确认：所有成功完成的激励广告（包含复活）共同累计，默认 n=3；累计 n 次后，道具获取出现一次分享，成功分享后重新累计；复活始终只能看广告。新增共用后台独立配置菜单，完成验证后部署后台。

## 方案与范围

采用游戏独立远程配置 + 客户端按玩家本地持久化的计数状态，沿用现有奖励获取成功回调和登录通道。相比仅修改打包 JSON，后台修改可以下发；相比服务端记录每次奖励获取，本方案保持当前本地路由机制，不新增奖励交易协议。计数不承诺跨设备同步，清除本地存储会重置。

不更改永久道具库存授权、历史接口、数据库业务标识、桥接协议和已有本地存档键。新增内部实现和新增状态使用 pot 命名；历史计数保留但不解释为真实广告次数，首次使用新规则从零开始。

## 状态与边界

- 同一玩家的四种道具和两种复活共享一个非负广告计数，跨局、重启保留，玩家之间隔离。未登录状态与已登录玩家隔离，不合并历史匿名计数。
- 普通道具需要激励获取时：计数小于 n 展示广告；达到 n 展示分享。原有库存使用不计数，也不消费分享机会。
- 复活无条件选择广告，不允许免费或分享回退；广告禁用或不可用时显示不可用或可重试状态，不发放复活。
- 达到 n 后继续通过复活完成广告，分享机会保持待用；只保留一次机会，不叠加多次。成功分享将广告计数归零。
- 广告只在完整观看且对应奖励实际应用成功后加一；失败、取消、提前退出、重复回调不推进。分享只在现有分享完成判定且道具实际应用成功后归零。
- 计数可超过当前 n（仅作安全整数范围保护）；修改 n 后用现有计数重新比较，不清空计数。提高 n 可能暂时收回尚未消费的分享资格，降低 n 可立即使下一次道具满足分享条件。
- 禁用分享时道具继续走广告，保留累计值；禁用广告时未达阈值的道具不可用，不提前改为分享。达到阈值且分享开启时道具可分享。复活始终遵守只能广告。
- 展示中的 offer 捕获路由和配置版本；配置更新不抢占正在进行的广告/分享，已启动的操作按启动时快照成功结算一次。尚未启动的旧 offer 失效时提示重开，不误发奖励。
