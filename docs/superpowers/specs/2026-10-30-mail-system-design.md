# 邮件、通用确认框及菜单入口

用户已确认完整服务端方案，并指定邮件入口位于左上角展开菜单第三项。通用弹窗使用普通框 PSD，动态标题、正文及左右按钮，确认后才领取。

## 范围与结构
- PSD 59 的 01 组导出信封、标题、未读/已读卡片；PSD 102 导出通用背景及按钮；PSD 144 导出菜单。临时副本隔离图层，裁透明边，按 720×1280 下实际尺寸缩小，单张最大 1024，不改原 PSD。
- Unity 独立 Mailbox、CommonDialog、HomeMenu prefab；列表可滚动、正文可滚动、空列表及网络错误可重试。入口和菜单邮件项显示未读或未领取红点。
- 复用 ReplicaInvitations 微信身份和库存，序列化同一个服务对象上的网络操作，避免邮件领取和道具扣除响应覆盖库存。
- 服务端邮件支持官方公告、三种已有道具奖励，全服或单个 inviteCode。受独立运营密钥保护的发送接口和本地 CLI。正文纯文本，不执行富文本。
- 邮件模板不可修改、发送 ID 幂等；用户回执和库存增量在同一数据库事务。已读与已领取独立。确认重试不重复奖励。已过期邮件不可首次领取。
- 分页目录存储，按新到旧加载；收件人和状态校验在服务器。用户 token 不能发邮件，运营密钥不进入 Unity。

## 验证
服务端测试公告/定向/全服、未授权、取消不领取、并发及重试幂等、超时重试、到期、分页、输入限制；Unity 编译及 prefab 生成，720×1280 截图检查布局。生产部署与双账号微信真机测试单独报告。
