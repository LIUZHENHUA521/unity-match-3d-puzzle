# 回放缓存积压修复

用户已同意上一轮提出的三项修复：旧非胜局缓存预算、压缩保留进度、荣耀状态区分。本轮完成实现与验证，不自动部署。

## 方案

不扩大缓存上限（会继续堆积），不整体清空（会丢失可补传胜局）。采用有界非胜局保留、运行中压缩暂停续做和明确失败状态。

### 缓存

新增 PotReplayRetention。只处理当前账号、账本结果为 fail/quit/incomplete 且载荷元数据也确认不是 win 的已结束录像。未知、元数据损坏、胜局、正在录制或压缩/上传的文件一律保留。非胜局保留预算 32MiB、最多 3 局、最长 2 天；按旧到新淘汰，且在录像目录总量超过 64MiB 时继续回收可淘汰非胜局，给一局最多 64MiB 的录制预留空间。128MiB 开局硬门槛继续存在；如果全是不可淘汰胜局，则不能承诺新局一定可录。

所有同局文件一起回收，账本保留 failed/缓存清理原因，不删除通关/奖状记录。对正在工作的载荷用服务侧生命周期保护，避免关闭仍在使用的流。启动恢复前、开始新局前和一次上传结束后执行回收。保护不同账号的文件；统计总量可以跨账号，淘汰不能跨账号。

保留时间使用独立 retainedAt，重试不刷新；历史账本第一次遇到时从 updatedAt 迁移。按文件大小一次快照计算预算。删除中断仍保留明确清理原因；未知或元数据冲突不进入候选。

活动文件保护同时覆盖 Recover 逐帧恢复与完整 UploadOne 生命周期；原有 Reconcile 在修改状态或删文件前也必须跳过活动记录。恢复循环同样在游戏忙碌时暂停、账号切换或服务销毁时取消并释放流，防止开始新局时把正在恢复的 journal 标记失败并删除。

### 压缩

保留现有 gzip-v1 协议与原子 .packing -> .packed。将中断条件拆成 cancel 与 pause。新局、播放回放、短期内存保护等 Busy 只暂停迭代，同一次进程中保留 gzip/输入流进度；回到空闲时继续，不删除 .packing。账号切换/服务销毁取消，原始载荷保留、部分 gzip 清理。进程退出仍从原文安全重试，不声称支持跨进程压缩断点。暂停时不做压缩写盘，并避免长帧阻塞。

### 荣耀

服务端 honors 增加兼容字段 replayState：ready/pending/uploading/unavailable。ready 索引优先；缺索引时仅使用匹配 recordId/runId 的原对局诊断，failed -> unavailable，queued -> pending，uploading -> uploading；未知或只有 synced 诊断仍 pending，不虚构可播放索引。保留 replayId 原协议；不返回原始错误或用户标识。

客户端统一映射：可回放、回放待同步、回放同步中、本局未保存。无新字段时兼容旧服务；本机相同账号和 recordId 的 failed 账本可补充判定未保存。点击未保存时明确本局没有完整录像，通关与奖状不受影响；等待状态继续提示首页联网同步。

## 验证

- 真实 Unity 序列化与流式 gzip：压缩推进后暂停，输出大小在暂停时不增长，恢复得到完整可解压字节，取消保留原文，既有长局/重试测试继续通过。
- 缓存：多局失败挤占超过门槛后回收并为新局留空间；保护胜局、未知/损坏元数据、其他账号、活动载荷；按容量/数量/年龄验证。
- 服务端：正常索引覆盖 failed 诊断；缺索引 failed/queued/uploading；runId 不一致；字段泄露与账户隔离回归。
- Unity 荣耀：新状态文字/点击说明与旧接口兼容、ready 优先；现有荣耀和回放验证通过。
- 未连接真机，自动验证不可冒充实机连续多局验收。线上缺失帧不能恢复，不修造数据。
