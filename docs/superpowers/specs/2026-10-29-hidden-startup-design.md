# Hidden second-stage startup optimization

User approved optimizing startup while explicitly preserving initially invisible objects as invisible. No gameplay rule, layout/random draw, type budget, sorting, collider, pickability, visibility threshold, growth or completion gate changes.

Chosen approach: (1) retain initial first-stage resource warm-up, then incrementally stock up to six inert copies per second-stage prefab, one copy per rendered frame after first-stage creation finishes; (2) skip fixed .02-second display delays for initially hidden creation entries only, bounded by the existing 2.5ms slice budget plus a cap of 12 hidden creations per frame. Visible entries retain the global index modulo-three schedule and all .5/.2/.3 completion waits. Hidden/visible classification uses the exact initial spawn-height threshold already used by Register, not current physics positions. No random work is moved into preload. All objects still pass through normal CreateBoardItem and Register in the same sorted order. The optimization changes wall-clock scheduling; it does not promise bit-identical dynamic physics or a device performance number.

Alternatives rejected: making hidden objects visible changes gameplay; creating all 300 synchronously risks a hitch; precomputing the next layout during stage one changes shared random consumption and session timing. Memory is bounded by six copies per catalog prefab, sharing asset meshes/materials; cancellation and fallback use existing prefab-keyed pool lifetime. Partial warm-up never blocks handoff. Prepare adds at most one missing copy per call, never creates gameplay bindings or activates clones.

Validation: compare legacy and optimized production iterators from the same seeded stream with physics disabled: same IDs/types/positions/rotations, same hidden render/pick/rigid state; only scheduled hidden waits differ. Verify 12 cap with unlimited test budget and one-per-frame with zero budget; hidden objects remain hidden across the live startup. Verify first-stage warm clones inert, RNG unchanged, cancellation/home and early transition, and completed cached clones actually reused. Run existing creation budget and first-stage integration regressions; local WeChat build, no upload. Record low-overhead warm handoff first-visible timings and cache counts separately from phone claims.
