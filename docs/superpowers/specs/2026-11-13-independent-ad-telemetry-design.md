# 3D 广告完成独立上报

2026-11-13。用户已确认采用广告完成立即持久化、独立补传、服务端去重，并更新共用后台的方案。

## 问题与目标

当前 GooseReviveAds.jslib 在微信 onClose(isEnded=true) 后通知 Unity，只有道具或复活效果生效后才累加内存计数，Match3DGameRecords.Finish 才保存结算队列。广告完成后未结算退出会漏记；取消或销毁 Unity 组件还可能丢失完成回调。目标是广告完成记录不依赖关卡结算和 UI 生命周期，并对重传保证只计一次。客户端上报仍不是微信结算收入或防作弊证明。

## 选择

采用独立事件队列。仅补退出结算不能覆盖闪退，定时同步累计数仍有窗口与并发覆盖问题。新事件与旧结算分开储存、展示，不能相加。

## 事件与上下文

一次播放前生成稳定 impressionId，并冻结 owner、recordId、runId、stage、placement（四种道具、两种复活）、adUnitId、clientVersion、platform。复用当前播放 requestId 作为 impressionId。身份必须在播放前明确；登录未就绪不开始生产广告，提供重试提示。时间同时保存客户端 occurredAt 与服务端 receivedAt，补传按 occurredAt 归属日期。

第一版只新增 completed 事件。奖励实际生效继续使用现有结算 toolUsage/reviveUsage，后台将其明确标为“结算广告奖励生效次数”；completed 是独立的“广告完成次数”。不把完成直接当成奖励生效，不改红包资格和发放逻辑。编辑器、网页预览和模拟成功不进入生产事件。

## 客户端持久化与发送

持久化与重试在微信 JS 桥层实现，生命周期独立于 Unity 弹窗和场景。播放前同步写入 prepared 状态和冻结上下文；完成回调先将其同步更新为 completed，再通知 Unity。以微信本地存储保存版本化队列，立即发送；只在服务端明确确认相同事件 ID 后删除。prepared 不算完成，重启后不能将未确认播放猜测为完成。

重试使用带抖动的退避（上限 60 秒），在登录就绪、回前台和网络恢复时触发，同一队列仅有一个发送者。401 请求刷新现有登录，429/5xx/网络超时保留重试；400/409 隔离保留诊断，不阻塞其他有效事件。账号切换只发送归属当前账号的事件，异步响应按原事件归属确认，不能重绑定到新账号。仅在内存使用登录 token，不写入事件缓存。

业务 Cancel 只撤销奖励回调，不撤销已经开始展示广告的完成监听；仍维持全局播放互斥，直至 native onClose/onError 结束，防止旧关闭事件被归到下一次播放。加载阶段取消可清理未展示请求。重复和迟到回调通过播放状态及 ID 去重。后台切换导致 JS 暂停时依靠落盘队列恢复。

存储损坏、容量不足、同步写失败必须可见且不能静默覆盖旧 completed 事件。播放前无法可靠预留缓存时拒绝新播放并提示重试。完成时落盘失败保留内存事件并立即尝试发送、记录诊断，不影响已完成广告的正常奖励；此极端情况不可承诺跨进程不丢。用户清缓存、设备故障、微信尚未送达完成回调就终止进程亦无法保证零丢失。

## 服务端

在现有 goose-server 增加 POST /ads/events，沿用登录 Bearer token，服务端解析玩家身份，拒绝 payload owner 与会话不一致。仅接受有限长度/枚举/整数的事件字段，限制批量、请求大小和频率。允许离线补传；时间过于超前拒绝，过早事件保留诊断，不静默改写为接收日。

新集合 goose_ad_events，文档 ID 为 hash(owner + ':' + impressionId + ':completed')。事务中首次写入保存规范化字段与 receivedAt；同 ID 同内容返回同一成功确认，不重复计数；同 ID 不同内容返回冲突。关联关卡仅作分析，不能因为开局记录尚未到达或局已结束而拒绝广告事件。数据库禁止客户端直写，仅服务端写、后台授权读。

旧版 /records 与 /rewards 接口保持兼容；独立事件和结算接收顺序任意。新客户端开局记录标记 adTelemetryVersion=1，后台才能区分“支持实时统计、当前为零”和“旧版无实时数据”，不以没有事件猜测客户端能力。即使没有对应开局记录，事件仍可按玩家、完成时间查询。

## 验收

- 完成广告后未结算退出，重新启动仍能补传；尚未上传的 prepared 不计完成。
- 断网、401 刷新、429/5xx、成功响应丢失重传，最终唯一入库。
- 同 ID 内容冲突、重复关闭、旧回调、场景销毁与业务 Cancel 不重复发奖励或漏掉已展示广告的完成事件。
- 切账号时旧事件不会被新账号上传/归属；上传中切换身份的响应只确认原事件。
- 广告加载失败、未看完、分享与预览都不计 completed；效果不再可用但广告已看完仍计 completed。
- 存储失败和队列损坏有明确处理；隔离坏事件不堵塞正常补传。
- 独立事件先到、开局先到、无开局记录、未结算、旧版记录均正确展示；完成数与生效数不混加。
- 服务端鉴权、字段校验、事务并发去重及查询权限通过测试；现有广告重复播放与红包结算回归通过。
- 后台构建通过并按长期约定部署验证。服务端须先具备兼容接口，再发布客户端新包，最后验证真机播放/补传；发布状态与未发布部分分别说明。
