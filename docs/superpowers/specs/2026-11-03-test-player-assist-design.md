# 测试玩家手动三消模式

用户已批准：指定测试账号分批露出完整三连，仍手动点击，不需要洗牌；共用后台交付并部署。

## 账号与管理

复用 goose_invite_users 的 testAssist 布尔字段，默认 false。新增 adminGooseTestPlayers 云函数和 /goose-test-players 后台菜单，复用管理员 token、禁用账号和角色权限校验。按完整玩家 ID 查询已注册账号，开关通过原子 update 仅写 testAssist、testAssistUpdatedAt、testAssistUpdatedBy，不覆盖邀请和库存。字段仅经服务端登录/状态接口返回，客户端不能自行提交开关。管理员操作反馈下一次登录/新开局生效；不预先为任何用户启用。

## 游戏

单人新局锁定登录时获得的标记，未登录默认普通玩法，PVP 永远普通。测试布局使用原主题和原关卡全量物品，按类型分成完整三连，每波最多两组三连（六个物品），打散位置。只有当前一波可见、可点击；物体使用互不遮挡的屏幕布局、静止刚体，保留逐个飞槽和三消动画。下一波必须等当前波全部消除且动画完成后露出。未露出的物品仍计入剩余总数，避免提前通关；最后一波完整结束才结算。工具在测试布局禁用，避免移出/吸附/洗牌破坏批次约束。退出、重开、切关和PVP清理批次状态。测试布局显式提示“测试模式 · 手动三消”。

每波最多两种类型且数量均为三的倍数，即使混点也不会在七格槽产生不可消的满槽；必须验证真实射线可达性，而非仅依据 active 或 renderer 状态。

## 记录与奖励

测试布局用独立 levelVersion=test-assist-v1 标记普通闯关记录。测试账号普通游玩，不启动红包资格局；服务端拒绝测试账号申请红包局，并拒绝测试版本记录参与红包结算，以避免开关变化后的误发。原红包列表查看保持可用。

## 验证与交付

后端测试默认关闭、开关登录返回、身份/权限拒绝、非法ID/值、部分更新不覆盖库存、红包隔离。Unity验证混点完整关卡、批次推进、未露出不可点、不提前胜利、退出重开/PVP、普通路径不变，以及屏幕位置射线和边界。后台构建和权限注册检查。相关仓库只提交本任务改动；云函数、现有 goose-3d-pvp 服务和共用后台部署并核验。客户端先完成本地编译/验证，不擅自提交微信审核；最终明确客户端包更新状态。
