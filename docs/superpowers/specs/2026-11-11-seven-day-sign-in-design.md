# 七日累计签到

用户授权先设计奖励再直接实现。复用当前 Photoshop 的《弹窗-七日签到-蓝色.psd》，替换原稿的示例奖励和邀请按钮文案。

## 奖励与规则

| 天数 | 奖励 |
| --- | --- |
| 1 | 移出 ×1 |
| 2 | 加时 ×1 |
| 3 | 吸附 ×1 |
| 4 | 移出 ×2 |
| 5 | 洗牌 ×2 |
| 6 | 吸附 ×1、加时 ×2 |
| 7 | 移出、吸附、洗牌、加时各 ×2 |

按累计领取天数推进；漏签保留进度，不补领自然日。北京时间每天零点后可领一次，完成第七天后次日开始新一轮。道具进入已有永久库存，与每局免费次数及库存消费规则兼容。第一版不引入尚无消费功能的金币、碎片或背景奖励。

## 服务端

复用 goose-server 的微信身份和 users 集合。新增 /invites/sign-in/state、/invites/sign-in/claim；服务端配置是奖励唯一权威，响应包含七天配置、当天、当前轮次、已领天数、可领状态、服务端刷新时间。

签到进度和库存放在同一用户记录的一次数据库事务中提交。claim 发送 state 中的北京时间日期、轮次、天数，不能传奖励数量。对刚完成的同一请求返回幂等确认，其他旧日期/轮次拒绝并刷新。重复点击、并发、跨零点的超时重试均不能多发。日界线使用服务器时间；日期倒退不发奖。库存上限与邮件一致。

## 客户端与 UI

恢复首页入口，增加可领红点；不自动弹窗。弹窗采用原 PSD 背景、标题、关闭按钮、蓝色日卡和金色第七天卡。图标复用现有四种道具美术，奖励和天数用可编辑组件显示。已领蒙层+勾、今日高亮、未来待解锁；底部为立即签到/今日已签到/重试。说明累计规则与零点刷新。

沿用 Match3DInvitations 的账号、库存和串行请求状态，避免旧库存响应覆盖新签到库存。成功后展示现有领取奖励弹窗；失败不给本地库存加数。后台恢复、跨零点和重新打开会刷新状态；身份变更清掉旧状态。编辑器可以预览七天奖励，但不伪造线上奖励；本地验证使用模拟服务。

## 验证及交付

服务端测试涵盖七天奖励、漏签、北京时间零点、完整循环、并发、重复请求、跨日重试、无凭证/伪造数量/越级、库存上限与事务回滚，以及库存消耗兼容。客户端编译和模拟 HTTP 测试涵盖状态、成功/失败、超时重试、跨日、按钮与领奖弹窗。渲染长短屏截图检查美术。

没有新增后台管理功能。服务端实现与验证完成后按部署提醒技能询问部署；本轮请求未明确要求上线。
