# 每日同题与候选关卡发布

用户已确认采用全员每日同题：同一北京时间日期、同一档位使用同一关，重试不换局；攻略由玩家自行发现、分享，后台不填写答案。已授权实施及共用管理后台部署。

## 交付

沿用 crazyCombo/tasks/admin-platform 的每日关卡页面、路由与权限。保留主题、层数、数量、种类数、限时；增加生成/更换候选、候选文件下载、Unity 真实玩法试玩、固定布局与预览图回传、试玩确认、未来排期与当日锁定。第一版通过文件往返复用 Unity 编辑器，不另造不一致的浏览器物理游戏。

## 关卡数据与一致性

发布的 shared-v2 配置包含候选 ID、正整数 seed、固定布局（两关物品的 ID、类型、位置、旋转、缩放、可见与物理状态以及高度阈值）、资源版本。布局由 Unity 使用真实模型生成一次并保存，普通客户端直接还原；就绪前禁止物理推进，开始交互后恢复原有动态玩法。新协议 3，旧协议仍可完成已签发旧局，但不可进入 shared-v2 新局。

服务器不再按玩家为新 shared-v2 关卡抽签，按日期和档位在 goose_daily_levels 保存唯一当日快照，事务固定该日配置；玩家仍各有尝试、奖励、记录身份。当日/过去日期禁止后台重新发布，未来版本可替换；玩家日期以服务端北京时间为准。未排期时沿用最近已发布完整关卡，后台明确标记沿用。旧发布历史兼容读取；首次切换为未来某日的 shared-v2 发布，不能半天换题。尚未切换的旧关维持原行为，后台明确显示旧模式。

## 候选工作流

保存参数或换候选创建新候选 ID/seed，删除过期布局、截图及试玩确认；下载包含完整配置的候选文件。Unity 菜单载入候选，分别生成两关、保存开局状态及第二关截图，支持按固定状态重新试玩。回传包严格校验候选 ID、seed、配置、资源版本、每关数量/类型/三消组/有限坐标与归一四元数、图片格式大小；revision 乐观锁防止回传覆盖较新的候选。截图仅后台保存，不进入开局协议。发布要求有效布局且明确试玩确认。不得以人工备注替代真实布局。

## 验证与发布

Node 测试覆盖多人同题、并发、重试、日切、继承、锁定、旧协议、候选失效、导入校验、权限。Unity 隔离工程编译和 PlayMode 验证两关快照还原、物品数量/变换一致、退出重试、分享日期档位。管理端构建。只提交本任务文件，保留其他工作。按规范提交推送相关仓库，再部署云函数、goose-3d-pvp 服务、后台。构建上传 Unity 开发版本，不提审；部署后核对结果，区分自动验证与未做的真机测试。
