# 编辑器玩家独立关卡配置

## 已确认需求

在共用后台的「3D 游戏 / 每日关卡」增加第三个标签「编辑器玩家」。这里的玩家是 Unity Editor 内进入游戏的调试入口，不是需要在注册玩家列表中打标的新用户群体。

后台仅编辑按从下往上排列的层，以及每层物品数量、类型数量；支持新增和删除层。没有主题、指定模型、日期、限时、层高、加量、减量或固定开局配置。保存后下一次新开局读取，当前对局和重试保留本局配置。

用户明确：无需增加类型数量超出模型池时的自动裁剪或兼容策略，由用户控制；同意新增层高度由 Unity 本地规则补齐。保留现有生成器的基础合法性约束，遇到非法配置提示原因，不能静默改写数量或类型。

## 实现边界

- 管理后台：`crazyCombo/tasks/admin-platform/src/pages/PotDailyLevels.tsx` 增加标签及独立组件；沿用该页面现有菜单与权限，服务端读写也必须使用对应后台权限。
- 服务端：在 `crazyCombo/server/services/goose-server` 增加独立编辑器配置模块及读取入口，管理端写入沿用当前后台 API 的鉴权和配置存储模式。不得复用或改写每日已发布配置。
- Unity：`PotEditorBetaLevels.cs`、`TestStartupWindow.cs` 及 `Match3DFlow` 接入独立配置。保留旧内测预览能力和纯本地模式，增加明确的「后台编辑器配置」来源；未显式选择来源的新环境默认该模式，已有用户选择保持兼容。主题选择对新模式开放。
- 持久化数据仅含配置版本和有序 `{count, types}` 层数组及必要更新时间；使用独立 pot 标识。两档入口默认共用同一份调试配置，不新增档位配置，符合目前纯本地模式两档共用参数的行为。
- 不迁移历史接口、数据、请求头、凭据或本地存档键。新入口复用现有编辑器只读凭据机制，凭据仍只在忽略的 UserSettings 文件中，不进入游戏发布包。

## Unity 应用规则

第一关保持所选主题现有引导关。第二关克隆所选主题本地 Profile，不修改共享 ScriptableObject，只覆盖层数组的 count 和 types。主题、模型池、限时、可见高度及其他生成参数继续使用本地值，不读取每日快照或每日加减量。

已有层保留对应本地高度及权重，权重不得从其他主题复制。新增层高度取最后一层高度加步长；步长使用最后两个本地层的正高度差，否则取 2；没有本地层时首层高度取 14。新增层使用空权重数组，表示等权，不指定模型索引。

开局读取成功后冻结配置和主题用于本局两阶段及重试；重试不重新请求后台，也不受此时编辑器主题切换影响。新开局重新获取最新版。重复点击避免并发开局，离开页面后丢弃旧响应。继续免费道具、不发红包，不创建真实资格或奖励对局。

配置不存在、凭据缺失、网络失败、配置不合法时显示明确错误，不静默改用每日或本地关卡；用户可主动选择纯本地模式。后台空配置显示待配置状态，不自动覆盖保存示例数据。

## 保存与验证

保存即生效，无每日发布、排期或候选生成流程。后台与服务端约束正整数物品数量且是 3 的倍数、正整数类型数且不超过该层数量除以 3、至少一层；不根据主题限制类型数。使用配置 revision 防止多窗口旧数据覆盖新数据。

验证覆盖管理权限、保存/读取隔离、版本冲突、非法输入、编辑器凭据只读权限及正常玩家每日逻辑不受影响。Unity 扩展 `Tools/validation/PotEditorBeta/run.py`，验证主题目录全部主题、两档入口、第一关、第二关、重试、主题及配置冻结、新开局刷新、增删层高度、权重对应关系及失败提示。测试配置使用各主题合法类型数量，不实现自动裁剪。

## 交付

完成后台构建、服务端相关测试及 Unity 验证后，按项目规则提交推送并部署后台，确认线上版本。需要上线的配套服务端变更应纳入功能交付；不上传微信版本。部署前盘点目标仓库全部工作区有效改动，不静默漏发；无法安全纳入的内容说明具体原因。当前 Unity 中已有胜利流程等未提交改动，保留并避免覆盖。

## 用户后续调整：手动高度与本科默认值

用户要求显示高度配置并直接填入本科默认值。每层新增可选 height，大于 1.5 且不超过 30，Unity 优先使用所填高度；缺失时兼容原本地补齐规则。默认值直接来自后台 dailyLevelContract.defaultConfig("bachelor") 的 layers：150/23/14、60/10/18、45/8/20、45/7/22（数量/类型/高度），仅写编辑器独立文档，不复制主题或其他每日参数。

## 配置来源迁移修正

实机发现仅有旧 pot.editor.useEditorConfiguration=true 时，新版仍默认纯本地，导致后台配置不生效。改为只有新版 pot.editor.configurationSource 的明确选择可以覆盖默认来源；没有新版选择时始终使用后台编辑器配置。保留新版显式选择纯本地/内测模式。开局日志输出远程版本及完整层参数，便于核对。
