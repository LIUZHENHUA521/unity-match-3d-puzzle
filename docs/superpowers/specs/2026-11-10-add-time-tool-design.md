# 加时道具（用户已确认实施）

- 单人限时关卡新增“加时”，每次增加 180 秒，可重复使用；超时复活仍加 300 秒，二者次数独立。无计时关卡和 PVP 不开放加时。
- 道具显示顺序为移出、吸附、加时、洗牌；协议继续保留原编号 0/1/2，新增加时编号 3。库存、广告授权、失败退款、测试模式沿用现有链路。
- 从 Photoshop 当前游戏 PSD 的 img_btn_clock 导出透明图标，用临时副本导出“加时”文字；源文档保持不变。
- 服务端库存增加第四项，旧三项库存按第四项为零兼容。客户端通过 X-Goose-Tool-Count: 4 声明支持；旧客户端继续收到三项 inventory。邀请奖励仍只发原三种，不自动增加新奖励。
- 邮件奖励允许三项或四项；消费/退款支持 type=3 并保持幂等。记录兼容旧三项 toolUsage，新记录包含四项和广告使用量；加时凭证纳入红包结算核对。
- 记录保存真实剩余时间，用道具成功次数及独立复活时长限定可接受的最大剩余时间。
- 共用管理后台现有注册玩家页面增加第四项库存编辑，记录页面增加加时次数；保持原权限与并发修改保护。根据用户长期约定，完成验证后部署涉及的管理功能。

验证：后端旧数据/旧协议、消费退款、邮件幂等、库存并发保护和记录凭证；Unity 编译与运行时测试覆盖 +180、重复/过期广告回调、库存成功/失败、复活独立、无计时关卡、四按钮布局；后台构建和部署结果核验。

实施补充：旧后台的三项写入保留当前第四项，新后台四项比较全部库存。新客户端记录包含 timeReviveUsed，剩余时间上限为初始限时 + 加时总成功次数×180 + 超时复活标志×300；广告次数/复活仍沿用 client_reported 信任边界，不宣称服务端已验证广告。库存使用由消费凭证验证，实际耗时包含与倒计时不同的暂停口径，不直接从剩余时间上限减去 activeDurationMs。旧记录保持三项原形，以保留历史幂等比较。
