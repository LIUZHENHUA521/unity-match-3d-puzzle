# 每日关卡配套加量

用户已批准实施：最近一次第二关有效通关后 72 小时内，下次新开挑战使用加量版；再次通关续期，过期恢复。跨本科/清北统一按玩家最近通关计算，不叠加。第一关不变，第二关 layers[0] 固定增加生成时配置的 n。

## 配置和生成

沿用每日关卡菜单与权限。新增 potBoostCount，默认 60，允许 0，必须为非负 3 的倍数；第一层加量后不超过 600，总量不超过 1200。新增 potBoosted 保存独立候选 ID、种子和完整固定布局。两版主题、限时、类型、高度和其余层数量一致；教学第一关共用普通版快照。配置变更同时废弃两版布局。后台自动连续生成两版、原子导入、原子发布，分别可试玩和显示预览。沿用排期也按整对沿用，不能只发布半套。历史无配套配置继续兼容，重新保存后升级为配套。

## 玩家发放与结算

每日共享存储保持原集合与键，存储整对快照；按服务端保存的 potLastWinAt 选择普通/加量版，响应只含选中的布局及 potVariant、potBoostCount，不传另一版。加量版沿用发布版本、使用独立候选/种子，run.level 锁定完整选中快照，旧 run 重试不重新判定。

仅通过现有挑战身份、数量、时间和道具凭据校验的第二关胜利更新 potLastWinAt；以已校验结束时间和服务器当前时间的较小值为准，取与旧值的最大值。失败、第一关、普通记录上报、内测关卡不续期。重复终态请求不重复更新。红包额度不足不否认有效通关。旧记录保留，不更名、不重写存档、桥接协议、路由或集合。旧客户端可以还原所选完整 shared-v2 快照；新增 Unity 字段保留变体信息供录像，数量仍由服务器下发。

## 验证与交付

覆盖 n 边界、首层差值、两版原子导入发布、旧排期兼容、72 小时边界、续期和重复上传、跨档位、新旧局版本隔离。后台构建、真实 WebGL 两版生成与重开、Unity 隔离编译/运行验证。保留其他未提交改动，提交推送本任务代码，部署关联云函数、游戏服务及共用后台并核实结果。微信上传不提审。

## 边界补充

恰满 72 小时恢复普通版（0 <= now - potLastWinAt < 72h）；旧单版排期继续发原普通版，重新发布整对后，新开局读取更新的共享快照，旧 run 不变。通关时间、终态记录及奖励结果使用同一数据库事务提交，冲突重试后取最大时间，不允许成功终态丢失续期。
